# Reporting a vulnerability

[English](#english) · [한국어](#한국어)

## English

Report suspected website vulnerabilities privately to [miroven@mksdr.bid](mailto:miroven@mksdr.bid). Do not publish exploit details in public issues or pull requests before coordinating with the maintainer. This contact does not depend on GitHub private vulnerability reporting being enabled.

Include the affected page or component, commit or deployment date if known, reproduction steps using synthetic data, and the expected and observed impact. Share only the minimum information required to reproduce the issue. Never send personal journal content, photos, recovery codes, PINs, encryption keys, credentials, or session cookies.

Miroven-Web is a static product and information website. Journal authentication, encryption, synchronization, and storage belong to the separate client and API projects. Identify which project is affected; for client vulnerabilities, follow the [Miroven security policy](https://github.com/mksdr/Miroven/blob/main/SECURITY.md).

There is no published security maintenance schedule or guaranteed response time. A repository build check does not verify production hosting settings.

## 한국어

홈페이지의 취약점은 [miroven@mksdr.bid](mailto:miroven@mksdr.bid)로 비공개 신고해 주세요. 관리자와 조율하기 전에 공개 이슈나 PR에 악용 방법을 게시하지 마세요. GitHub 비공개 취약점 신고 기능의 활성화 여부와 관계없이 이 연락처를 사용할 수 있습니다.

영향받는 페이지·구성요소, 알고 있다면 커밋 또는 배포일, 합성 데이터를 사용한 재현 순서, 예상 및 실제 영향을 적어 주세요. 재현에 필요한 최소한의 정보만 공유하고 개인 기록·사진·복구 코드·PIN·암호화 키·인증정보·세션 쿠키는 보내지 마세요.

Miroven-Web은 제품과 사용 정보를 제공하는 정적 홈페이지입니다. 저널 인증·암호화·동기화·저장은 별도 클라이언트와 API 프로젝트가 담당합니다. 영향받는 프로젝트를 구분하고 클라이언트 취약점은 [Miroven 보안 정책](https://github.com/mksdr/Miroven/blob/main/SECURITY.md#한국어)을 따라 주세요.

보안 유지보수 일정과 응답 기한은 별도로 보장하지 않습니다. 저장소 빌드 검사는 실제 호스팅 설정을 검증하지 않습니다.
